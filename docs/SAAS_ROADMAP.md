## 2. 战略决策（已选定方案）

### 决策 1：用户定位
**选定 → C：兼顾散户和中产投资人**
- Pro 层（¥99/月）抓散户量，建立口碑
- Premium 层（¥299/月）抓高净值，提升 LTV
- 不做机构（销售周期太长，不适合个人创业）

### 决策 2：商业模式
**选定 → A：Freemium（免费+增值）**

| 层级 | 价格 | 包含 |
|------|------|------|
| Free | ¥0 | 3 只关注、基础评分、每日 5 次 AI 问答 |
| **Pro** | **¥99/月 或 ¥888/年** | 无限关注、AI 研报、组合追踪、邮件提醒 |
| **Premium** | **¥299/月 或 ¥2680/年** | AI Hedge Fund 委员会决策、批量扫描、企业微信推送、回测、API 访问 |

**为什么 Freemium**：
- 投研工具的特点是「价值要试用才知道」
- Free tier 是最便宜的获客渠道
- 转化率行业基准 2-5%（你只需 1000 个 Free 用户就有 30+ 付费）

### 决策 3：部署架构
**选定 → A：全栈部署 s48**

```
[用户浏览器]
    ↓ HTTPS
[Cloudflare CDN/反代]
    ↓
[s48 服务器 103.139.212.48]
├─ Nginx (443, 80)
├─ Next.js 前端 (3000)
├─ FastAPI 后端 (8000)
├─ vLLM 推理服务 (8001) ← 替代 OpenRouter
├─ PostgreSQL + pgvector (5432)
├─ Redis 缓存 (6379)
└─ Cron 定时任务（财报/行情入库）
```

**为什么 s48 而不是 Streamlit Cloud / AWS**：
- 已有硬件（沉没成本）
- 数据隐私可控（用户投资偏好）
- 推理本地化省 95% API 费用
- 唯一缺点：单点风险 → 用每日备份到对象存储对冲

### 决策 4：MVP 优先级
**选定 → 先付费墙 + 基础数据管道（不追求功能完美）**

理由：先验证愿付费，再投入产品深度。

## 3. 12 周路线图（按周分解）

### Phase 1：基础设施（W1-3）

#### W1：本地推理上线
**目标**：把 OpenRouter 调用全部切换到 s48 vLLM。

- [ ] **D1**：s48 部署 vLLM + 选择模型
  - 推荐 `Qwen2.5-72B-Instruct-AWQ`（中文好，A100 跑得动）
  - 或 `DeepSeek-V2.5-Chat`（双卡张量并行）
  - 暴露 OpenAI 兼容端点 `http://s48:8001/v1`
- [ ] **D2-3**：FastAPI/Streamlit 切换 base_url
  - 改 `src/ai/summarizer.py` 和 `api/routes/*.py` 的客户端配置
  - 加灰度开关（环境变量 `AI_PROVIDER=local|openrouter`）
- [ ] **D4**：性能压测
  - 目标：研报生成 < 30s，对话回复首 token < 2s
  - 不达标则降级用 Qwen2.5-32B
- [ ] **D5**：成本对比报告
  - 对比 1000 次调用的 OpenRouter 账单 vs 本地（仅电费）

**交付物**：vLLM API 上线 + 现有功能切换 + 成本节省 95%+ 报告

## 4. 合规红线

### ⛔ 绝对不做
- 出具具体买卖建议（"买入贵州茅台，目标价 2000"）
- 代客理财、汇集资金
- 提供基金/股票推荐组合让用户跟投
- 使用「投资顾问」「私募」「财富管理」等敏感词
- 微信群里直接喊单

### ✅ 可以做
- 提供研究框架和数据分析
- 「假设按巴菲特原则，这只股的评分是 X」
- 历史数据展示和回测
- 教育内容（投资课程、方法论解读）
- 用户自主决策的辅助工具

### 标配免责声明（每页底部 + 注册时勾选）
```
本产品提供投资研究辅助分析工具，所有数据、评分、AI 分析结论
均为框架性参考，不构成任何投资建议或推荐。
投资有风险，决策需谨慎，因使用本工具产生的任何投资损失由用户自行承担。
```

### 主体定位
- 公司类型：科技公司（个体工商户起步）
- 经营范围：「计算机软件开发」「信息技术咨询」（**不**含「投资咨询」）
- 类比标杆：雪球（社区 + 工具）、且慢（基金代销，已转向工具）

## 5. 风险地图

| 风险 | 概率 | 影响 | 对冲方案 |
|------|------|------|----------|
| 数据源被封 | HIGH | HIGH | 至少 3 个备用源 + Redis 缓存兜底 + 历史数据库 |
| 监管/合规问题 | MEDIUM | CRITICAL | 律师函审查 + 严守红线 + 禁敏感词 |
| 微信封号/封禁公众号 | MEDIUM | HIGH | 邮箱+手机号兜底登录 + 多公众号矩阵 |
| 获客成本过高 | HIGH | HIGH | Freemium + 内容营销 + 推荐返现 |
| 客户留存低 | MEDIUM | HIGH | 每日盘前盘后推送 + 周报 + 关键事件提醒 |
| s48 单点故障 | LOW | HIGH | 每日 backup 到对象存储 + 监控告警 + 域外备份 |
| 模型质量不稳定 | MEDIUM | MEDIUM | 双模型对比（vLLM + OpenRouter 兜底）+ 用户反馈机制 |
| 个人精力不足 | HIGH | HIGH | 每周固定 20-30 小时 + 不接定制 + 拒绝 scope creep |
