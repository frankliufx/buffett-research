# Stock Analyst 优化升级设计文档

**日期**: 2026-06-18  
**目标**: 将 stock-analyst 升级为 Sage 商业化产品的专业投研平台（面向专业投资者 + 高净值用户）  
**策略**: 保持 Streamlit，功能先行，双周迭代，三轨并行  

---

## 一、整体策略

```
Week 1-2  P0 数据源重构（稳定性 + 多源校验）
Week 3-4  P1 AI 分析深度（思维链 + 自我批判）+ UI 第一轮
Week 5-6  P2 数据+AI 整合打磨 + UI 第二轮
```

**核心约束**：分析页所有现有功能不得断，数据源切换必须向后兼容。

## 二、数据源升级（P0）

### 2.1 现状问题

- yfinance 不稳定，频繁超时或返回空数据
- A 股财务数据依赖新浪/腾讯爬取，接口随时可能失效
- 无数据质量校验层，错误数据静默流入分析引擎

### 2.2 新增数据源

| 数据源 | 覆盖范围 | 成本 | 优先级 |
|---|---|---|---|
| **Tushare Pro** | A 股全量：行情、财务、资金流、公告 | 免费积分制 | P0 |
| **SEC EDGAR** | 美股官方财务数据（10-K / 10-Q） | 完全免费 | P0 |
| **Alpha Vantage** | 美股实时行情 + 基本面 | 免费 500次/天 | P1 |
| **财联社 API** | A 股实时快讯、公告推送 | 低成本付费 | P1 |
| **Polygon.io** | 美股高质量实时数据 | 免费基础版 | P2 |

### 2.3 数据质量层架构

```
数据源 A ──┐
数据源 B ──┼──→ CrossValidator → 可信数据层 → Redis 缓存 → 分析引擎
数据源 C ──┘        │
                    ↓
              差异 > 5% → 标注 ⚠️ 不确定，不静默返回
```

**CrossValidator 规则**：
- 同一指标两个来源差异 > 5%：标注不确定，UI 显示 ⚠️
- 单一来源超时/失败：自动 fallback 到备用源
- 数据超过 TTL 且刷新失败：显示"数据截至 XX 时间"，不报错崩溃

### 2.4 向后兼容策略

- 新数据源以 **适配器模式** 接入，对外接口与现有 `src/data/*.py` 保持一致
- 每个数据函数保留原有签名，内部替换实现
- 新增 `src/data/adapters/` 目录，每个数据源一个适配器文件
- 分析页调用链不变，零改动

```
pages/2_analysis.py
    └── src/analysis/moat.py
            └── src/data/financial.py  ← 接口不变，内部切换到新源
                    └── src/data/adapters/tushare.py  ← 新增
                    └── src/data/adapters/sec_edgar.py  ← 新增
```

## 三、AI 分析深度升级（P1）

### 3.1 现状问题

- 大师分析结论表面，缺乏具体数字支撑
- 没有对立观点测试，分析容易变成"确认偏差"
- 输出格式不统一，不同股票报告结构差异大

### 3.2 结构化思维链（CoT Prompting）

强制每个大师分析经过四步：

```
Step 1 数据收集    → 列出所有相关财务指标（必须引用数字）
Step 2 假设验证    → 核心投资论点是否被数据支持
Step 3 反驳测试    → 找出最强的 3 个做空理由
Step 4 最终结论    → 综合以上，给出评级 + 目标价区间
```

### 3.3 自我批判机制（Critic-Refine）

```
初稿分析 → [Critic Agent] 扮演空头，挑战每个论点
         → [Refine] 修正被挑战的部分
         → 最终报告（含"主要风险：已考量"标注）
```

### 3.4 投研报告标准化格式

```
执行摘要（3 句话）
├── 核心论点 × 3（每条附数据来源）
├── 主要风险 × 3（量化影响）
├── 估值区间（熊 / 基 / 牛 三情景）
└── 建议（买入 / 持有 / 减持 + 目标价）
```

### 3.5 数据注入 Prompt

新数据源（SEC EDGAR / Tushare）数据直接注入 prompt context：

```python
context = {
    "financials": sec_edgar.get_financials(symbol),   # 一手数据
    "peers": tushare.get_peer_comparison(symbol),
    "recent_news": clsapi.get_news(symbol, days=7),
}
# 注入到 summarizer.py 的 system prompt
```

## 四、UI 专业感升级（P2，Streamlit 范围内）

### 4.1 设计原则

**延续 Blackstone 暗金色方向，做精致而非推倒重来：**
- 底色：保持深色（`#0A0A0A` / `#111111`）
- 主色：金色（`#C9A84C`）用于标题、重要数字、高亮
- 辅色：冷灰（`#8A8A8A`）用于次要信息
- 成功/危险：`#2ECC71` / `#E74C3C`（去掉过于鲜艳的颜色）
- 字体：数字用等宽字体（`font-family: 'SF Mono'`），文字用无衬线

### 4.2 四个重点改进

**① KPI 卡片升级**
```
当前：纯文字平铺
目标：
┌─────────────────────┐
│  ROE              ↑ │
│  23.4%     +2.1pp   │
│  行业均值: 15.2%    │
└─────────────────────┘
带趋势箭头 + YoY 对比 + 行业基准线
```

**② 数据表格升级**
- 关键列（ROE / PE / 护城河评分）颜色热力图
- 表头可排序
- 超阈值自动高亮（ROE > 15% 金色，< 8% 灰色）

**③ 图表升级**
- K 线 + 均线叠加（MA20/MA50/MA200）
- 技术指标子图（RSI / MACD）
- 所有图表统一暗色主题 + 金色高亮

**④ 分析报告卡片化**
```
当前：一大块文字
目标：
┌─ 巴菲特 ──────── 强烈买入 ⭐⭐⭐⭐⭐ ─┐
│ 核心论点：...（折叠展开）              │
│ 主要风险：...                         │
│ 目标价：$180-$210                     │
└─────────────────────────────────────┘
```

### 4.3 不改动的部分

- 页面路由结构不变
- Streamlit 组件不替换为第三方库（保持稳定）
- 现有功能入口位置不移动（用户习惯保留）

## 五、实施顺序与风险

### 优先级

| 模块 | 优先级 | 预估工作量 | 风险 |
|---|---|---|---|
| 数据适配器层 + CrossValidator | P0 | 3-4天 | 低（不改接口） |
| Tushare Pro 接入 | P0 | 1天 | 低 |
| SEC EDGAR 接入 | P0 | 1-2天 | 低 |
| CoT + Critic-Refine | P1 | 2-3天 | 中（需调试 prompt） |
| 报告格式标准化 | P1 | 1天 | 低 |
| UI 主题精化 + KPI 卡片 | P2 | 2天 | 低 |
| 图表升级 | P2 | 2天 | 低 |

### 关键风险

1. **Tushare 积分限制**：免费积分有每日上限，需加缓存降低请求数
2. **SEC EDGAR 解析复杂度**：10-K XML 解析需要较多适配工作
3. **Prompt 成本上升**：CoT + Critic 会增加 token 消耗约 2-3x，需评估成本
